# CineConnect – Database Design & Migration Guidelines

This document details the database architecture, ORM standards, and migration workflows for CineConnect.

---

## 1. Relational Persistence Stack

- **RDBMS**: PostgreSQL 16.
- **Python Driver**: `asyncpg` (high-performance asynchronous driver).
- **ORM**: SQLAlchemy 2.0 (modern DeclarativeBase syntax with type annotations).
- **Migration Tool**: Alembic (asynchronous runner configured in `backend/alembic/env.py`).

---

## 2. Table & Column Naming Conventions

All database identifiers follow PostgreSQL best practices:
1. **Tables**: Lowercase plural snake_case (e.g., `users`, `profiles`, `job_listings`, `applications`).
2. **Columns**: Lowercase snake_case (e.g., `first_name`, `is_active`, `created_at`).
3. **Primary Keys**: Always named `id` using UUID (`UUID(as_uuid=True)`) or BigInteger.
4. **Foreign Keys**: Target singular name suffixed with `_id` (e.g., `user_id`, `company_id`).
5. **Timestamps**: Every table must include UTC timestamps:
   - `created_at`: Default to `server_default=func.now()`
   - `updated_at`: Default to `server_default=func.now()`, `onupdate=func.now()`
6. **Soft Deletes**: Use nullable `deleted_at` timestamp rather than hard deletion where audit trails are required.

## 3. SQLAlchemy 2.0 Model Example Pattern

When implementing future entity models in `backend/app/models/`, adhere to the following template:

```python
import uuid
from datetime import datetime
from sqlalchemy import String, DateTime, func, ForeignKey
from sqlalchemy.dialects.postgresql import UUID
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.db.base import Base


class User(Base):
    __tablename__ = "users"

    id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        primary_key=True,
        default=uuid.uuid4,
    )
    email: Mapped[str] = mapped_column(
        String(255),
        unique=True,
        index=True,
        nullable=False,
    )
    hashed_password: Mapped[str] = mapped_column(
        String(255),
        nullable=False,
    )
    is_active: Mapped[bool] = mapped_column(
        default=True,
        nullable=False,
    )
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        nullable=False,
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        onupdate=func.now(),
        nullable=False,
    )
```

## 4. Alembic Migration Workflow

All schema modifications must be applied exclusively via Alembic migrations. Direct modification of live database tables is prohibited.

### Step 1: Register Models in Alembic
When introducing a new model in `backend/app/models/`:
1. Import the model in `backend/app/models/__init__.py`.
2. Ensure `backend/alembic/env.py` has access to `Base.metadata`.

### Step 2: Generate an Autogenerated Revision
Activate your virtual environment and execute:
```powershell
cd backend
alembic revision --autogenerate -m "create users and profiles tables"
```

### Step 3: Inspect the Generated Migration
Open the newly created script in `backend/alembic/versions/`:
- Verify column types, nullable flags, unique constraints, and foreign keys.
- Check both `upgrade()` and `downgrade()` functions.

### Step 4: Apply Migrations
Apply all migrations to the active database:
```powershell
alembic upgrade head
```

### Step 5: Rollback (if needed)
Revert the previous migration step:
```powershell
alembic downgrade -1
```

## 5. Connection Pooling Best Practices

The database session pool is managed by `app/db/session.py`.
- Always acquire sessions via the `get_db` FastAPI dependency:
  ```python
  @router.get("/users")
  async def get_users(db: AsyncSession = Depends(get_db)):
      ...
  ```
- Never create ad-hoc unmanaged database engines or raw connections inside controllers.
- The `pool_pre_ping=True` setting automatically drops broken or timed-out connections from the pool before queries execute.
